# Досье

Настольное приложение для Windows 10/11 x64: поиск российских организаций и ИП, карточки с реквизитами, история, избранное, экспорт и каталог источников для проверки контрагента.

## Запуск для пользователя

Готовые EXE скачиваются на странице **[GitHub Releases](https://github.com/Randupy/checker-ooo/releases/latest)**, раздел **Assets**. Если выпуск ещё собирается, статус доступен во вкладке **[Actions](https://github.com/Randupy/checker-ooo/actions)**. Ссылки на файлы `/workspace/...` относятся к облачной рабочей папке и не являются публичными ссылками на скачивание.

В папке `release` после сборки доступны установщик NSIS и переносимая версия. В установщике можно выбрать папку установки. Для работы не нужны Node.js и отдельный сервер.

1. Откройте приложение и введите ИНН, ОГРН, ОГРНИП или название.
2. Для автоматического получения карточек откройте **Настройки**, добавьте **API-ключ DaData** из личного кабинета `dadata.ru` и повторите поиск. Нужен доступ к API подсказок организаций. Тариф и лимиты определяются поставщиком.
3. Откройте организацию, сохраните её в избранное или выгрузите данные в CSV/JSON.
4. В карточке выберите **Проверить в источниках**, чтобы дополнить проверку выпиской ФНС, судами, отчётностью и другими сведениями.

Без ключа доступны история запросов и каталог внешних источников. Кнопка **Посмотреть пример** открывает явно обозначенную вымышленную организацию; пример никогда не выдаётся за результат реального поиска.

## Что загружается автоматически

Через DaData: доступные поставщику наименование, тип организации, ИНН, ОГРН/ОГРНИП, КПП, регистрационный статус, даты регистрации/ликвидации, адрес, руководитель, основной ОКВЭД, уставный капитал и признак филиала. Недоступные поля отмечены как отсутствующие. Вкладка **Все данные API** и экспорт JSON сохраняют полный ответ поставщика — в том числе дополнительные поля, которые может предоставлять ваш тариф.

Поиск по названию возвращает до 20 совпадений; для точного результата используйте ИНН. ИНН и ОГРН проверяются по контрольным цифрам до запроса. Неизвестный статус не считается действующим. Для финансовых и юридических выводов подтверждайте сведения первичным документом.

Это 12 выбранных внешних источников и один подключаемый API, а не доступ ко всем существующим базам. Для сайтов без поддерживаемой ссылки на поиск приложение пытается скопировать ИНН/название в буфер обмена; вставьте его в форму сайта. Внешние сервисы могут требовать CAPTCHA, регистрацию, оплату или дополнительные условия поиска. Например, ФССП может потребовать регион и наименование. Автоматического обхода ограничений или неподтверждённого «рейтинга надёжности» нет.

## Разработка

Требуется Node.js **22.19+** или **24 LTS**, npm и графическая среда для обычного запуска Electron. Версии зависимостей зафиксированы в `package-lock.json`.

```sh
npm ci
npm run setup:desktop
npm run dev
```

Electron 45 устанавливает бинарный runtime отдельной командой `setup:desktop`. Если среда использует стандартный HTTP(S)-прокси, задайте `ELECTRON_GET_USE_PROXY=1` при его установке. TLS и проверка контрольных сумм не отключаются.

Веб-предпросмотр интерфейса:

```sh
npm run dev:web
```

В браузере доступны пример карточки, каталог, история, избранное и экспорт. Подключение ключа и запросы API реализованы только в настольной версии. Предпросмотр не сохраняет API-ключи в localStorage.

## Проверки

```sh
npm run build           # TypeScript, production-интерфейс и Electron main/preload
npm test                # Проверки ИНН/ОГРН, поставщика API, хранения и экспорта
npx playwright install chromium
npm run test:e2e        # Браузерные сценарии
npm run test:desktop    # Настоящий Electron, IPC, сохранение на диск и перезапуск
```

В Linux без графической среды настольный тест использует headless-режим и `--no-sandbox` только для тестового процесса. Обычное приложение не отключает sandbox. Для системного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` вместо загрузки браузера.

Тесты поставщика используют зафиксированные ответы и ошибки API, не расходуют ваш лимит и не подтверждают актуальность реальных сведений. Живой поиск проверяется вашим ключом в приложении. Windows DPAPI и работа установленного `.exe` требуют проверки непосредственно в Windows.

## Сборка Windows

```sh
npm run dist:win
```

Результат в `release`: NSIS-установщик, portable `.exe` и распакованное приложение `win-unpacked`. Основная целевая платформа — Windows 10/11 x64. Для выпуска подписанного приложения настройте стандартные переменные подписи electron-builder в своей сборочной среде; закрытые ключи не хранятся в репозитории. По умолчанию сборка не подписана.

Для portable-версии отдельно: `npm run dist:portable`. Для полного NSIS-установщика рекомендуется Windows runner из GitHub Actions. При кросс-сборке NSIS в Linux требуется работающий Wine; закреплённый toolset 1.0.1 загружается с проверкой контрольной суммы, но его runtime не запустился в текущем облачном образе (`ntdll.dll`, `c0000135`). Это ограничение сборщика установщика, а не Electron-приложения.

В облачной среде с домашней папкой только для чтения выполните `bash scripts/setup-cloud.sh`, а перед кросс-сборкой задайте `XDG_CACHE_HOME=/tmp/checker-xdg-cache` и `ELECTRON_BUILDER_CACHE=/tmp/checker-builder-cache`.

GitHub Actions в `.github/workflows/build.yml` проверяет код в Linux, запускает настольный тест в Windows и собирает Windows-артефакты. Push тега `v*` после успешных проверок публикует установщик, portable-версию и контрольные суммы в GitHub Releases. Обычный push ветки только проверяет и собирает приложение; скачивание его артефактов доступно из соответствующего запуска Actions.

## Данные и безопасность

- Renderer работает с `contextIsolation`, без Node.js и с включённой песочницей. Привилегированные операции доступны только через ограниченный preload-мост; IPC проверяет отправителя и структуру аргументов.
- Внешние ссылки создаются из фиксированного каталога HTTPS-источников. Произвольные URL от renderer не передаются системной оболочке.
- API-ключ не возвращается в renderer. В Windows используется `safeStorage`/DPAPI; файл `api-key.enc` находится в `%APPDATA%\Dosye`. В Linux требуется защищённое хранилище ОС; незашифрованный fallback запрещён.
- История, до 200 избранных и до 50 недавних карточек записываются локально в `state.json` в папке данных приложения. Запись последовательная и атомарная. Повреждённый существующий файл не перезаписывается автоматически.
- При API-поиске запрос уходит на `suggestions.dadata.ru` по HTTPS. Внешние сайты получают запрос при открытии соответствующей ссылки. Стандартные переменные HTTP(S)-прокси поддерживаются.
- Шрифты поставляются вместе с приложением. Телеметрия, аналитика, внешняя загрузка шрифтов и сервер приложения отсутствуют.
- Избранное хранит снимок данных; для обновления выполните поиск заново. Очистка истории удаляет запросы и недавние карточки, сохраняя избранное.
- Экспорт CSV содержит UTF-8 BOM и разделитель `;` для Excel. Формулы из входных данных нейтрализуются. Экспорт JSON включает исходные поля API и дату получения.

## Структура

```text
electron/           Основной процесс, API, защищённый ключ, локальное хранилище, IPC
src/                React-интерфейс и браузерный предпросмотр
src/shared/         Типы, валидация, каталог источников, экспорт
tests/              Модульные, браузерные и настольные проверки
scripts/            Сборка main/preload и запуск разработки
assets/             Иконки приложения
```

Новые внешние источники добавляются в `src/shared/sources.ts`. Для автоматического получения данных из нового сервиса потребуется отдельный API-адаптер, разрешённый доступ и тесты его ответа.
